# セキュリティモデル

このキットは「機密データを端末の外に出さない」ことと、「AI に渡すツールで端末を危険にさらさない」ことの 2 つを目標にしています。このページでは、何が守られていて、何が守られていないかを説明します。

## 信頼境界

```
 [クラウド] Copilot Fusion ──(ツール呼び出しの引数と戻り値)──▶ [端末] spark-vibe ──▶ LM Studio (localhost)
                                                                        └──▶ nvidia-smi
                                                                        └──▶ 許可されたスクリプト（gpu_profile_run）
```

- クラウドに届くのは、**ツールの戻り値**と、Fusion がクライアントの機能で直接読んだファイルの内容です。
- spark-vibe と LM Studio の間の通信は `localhost` で完結します。`SPARK_LMSTUDIO_URL` を外部のホストに変えると、この前提は崩れます。

## 何が外に出るか

| ツール | クラウドに返す内容 | 返さないもの |
|---|---|---|
| `scan_secrets` | ファイルパス、行番号、シークレットの種類 | シークレットの値 |
| `repo_index` | チャンク数、ファイル数、所要時間、索引の場所 | コード、ベクトル |
| `repo_search` | 相対パス、行範囲、スコア | コード本文 |
| `private_ask` | ローカル LLM の要約（墨消し済み） | 検索したチャンクの本文 |
| `gpu_status` | GPU の状態 | — |
| `gpu_profile_run` | 実行した argv、終了コード、統計値、出力の末尾 3,000 文字 | — |
| `visual_review` | 判定の JSON | 画像 |
| `local_critique` | 判定の JSON | — |

### 注意が必要な点

- **`private_ask` の回答**には、ローカル LLM が要約したコードの説明が含まれます。システムプロンプトで長いコードの再現を禁じていますが、短いコード片が含まれることはあります。
- **`gpu_profile_run` の `output_tail`** には、計測対象のプログラムが出力した内容がそのまま入ります。ベンチマークがシークレットを出力しないようにしてください。
- **Fusion がファイルを直接読む**と、その内容はクラウドに送られます。UC1 のプロンプトは「最小範囲だけ読む」と指示していますが、技術的な強制ではありません。

## シークレットの墨消し

| タイミング | 処理 |
|---|---|
| `repo_index` で索引を作る前 | 各チャンクを墨消しし、墨消し後のテキストだけを `chunks.json` に保存 |
| `private_ask` の回答を返す前 | 回答をもう一度墨消し |
| `local_critique` に候補を渡す前 | 候補を墨消し |

検出パターンは [ツールリファレンス](./tool-reference.md#scan_secrets) を参照してください。正規表現による簡易検出なので、パターンにないシークレット（独自形式のトークン、ハードコードされたパスワードの一部など）は検出できません。

実測では、一致する 5 種のダミー秘密は索引・回答に現れませんでした。一方、未知形式の対照用 salt は索引に残り、秘密を要求する質問で 5 回中 4 回、戻り値に現れました（行番号付きの既定方式）。通常の回答にも 25 回中 11 回、コード行の逐語引用がありました。**「コードや秘密が絶対に外に出ない」仕組みではありません。** 社内固有の秘密形式を `SECRET_PATTERNS` に追加するか、機密ファイルを索引対象から外してください。完全な送信禁止が必要なデータには使わないでください。

これはダミー値の戻り値検査であり、実際のクラウド送信をパケットキャプチャで検証したものではありません。詳細は [UC1 の実測](./use-cases/uc1-private-fusion.md) にあります。

## gpu_profile_run の許可リスト

`gpu_profile_run` は、AI がホスト上でプログラムを実行できる唯一のツールです。任意コマンドの実行を防ぐため、次の多層防御を組み込んでいます。

| 層 | 対策 | 防ぐもの |
|---|---|---|
| 1. シェルを使わない | 文字列ではなく `argv` 配列で受け取り、`shell=False` で実行 | `&` `\|` `;` などによるコマンド連結、リダイレクト |
| 2. ランチャーを固定 | `argv[0]` は `python` / `pytest` / `node` の名前だけ。実行ファイルはサーバー側で決める | `cmd`、`powershell`、任意の `.exe` の実行 |
| 3. 形式を固定 | `python <script>.py` / `python -m pytest` / `pytest` / `node <script>.js` だけを許可 | `python -c`、`python -m <任意モジュール>`、`node -e` などのインライン実行 |
| 4. 場所を限定 | スクリプト、pytest のターゲット、`cwd` は `SPARK_PROFILE_ROOTS` 配下。`..` とシンボリックリンクは解決してから判定 | 許可フォルダー外のスクリプト実行、パストラバーサル |
| 5. pytest の危険なオプションを拒否 | `-p` `--pyargs` `-c` `--config-file` `--rootdir` `--confcutdir` `--import-mode` | 外部のプラグインや設定ファイルの読み込み |
| 6. リソースの上限 | タイムアウト 1〜3600 秒、サンプリング間隔 0.1〜10 秒 | 無限に続く実行、過剰なサンプリング |
| 7. 呼び出し側から変更不可 | 許可ルートと Python の実行ファイルはサーバーの環境変数でだけ設定 | AI が自分で許可範囲を広げること |
| 8. クライアント側の承認 | VS Code / Copilot CLI のツール実行確認 | 意図しない呼び出し全般 |

E2E テストでは、次の 11 パターンが**実行されずに拒否される**ことを確認しています: `cmd /c`、`powershell -Command`、Python の絶対パス指定、`python -c`、`python -m http.server`、許可フォルダー外のスクリプト、`.py` 以外のファイル、許可フォルダー外の `cwd`、pytest の `-p`、許可フォルダー外の pytest ターゲット、`node -e`。

### 残るリスク

- **許可フォルダー内のスクリプトの中身は制限しません。** 許可フォルダーに悪意のあるスクリプトがあれば実行されます。また、Fusion がそのフォルダー内のファイルを編集できる場合、編集してから実行するという流れも可能です。**信頼できるリポジトリだけを登録**し、ツール実行の確認を有効にしたままにしてください。
- **pytest は `conftest.py` と `pytest.ini` などを読み込みます。** これらも許可フォルダー内のコードとして扱われます。
- **スクリプトへの引数は検査しません。** スクリプト自身が引数を安全に扱うことが前提です。

## ローカルに保存されるもの

| 場所 | 内容 | 削除方法 |
|---|---|---|
| `<repo>/.spark-index/` | 墨消し済みのチャンク、ベクトル | フォルダーを削除 |
| `%APPDATA%\Code\User\mcp.json.bak-*` | セットアップ前の VS Code の MCP 設定 | 不要なら削除 |
| `%USERPROFILE%\.copilot\mcp-config.json.bak-*` | セットアップ前の Copilot CLI の MCP 設定 | 不要なら削除 |

## 運用のおすすめ

1. 新しいリポジトリでは、まず `scan_secrets` を実行し、検出されたシークレットはローテーションしてからコードから取り除きます。
2. `SPARK_PROFILE_ROOTS` には、計測が必要なリポジトリだけを登録します。作業が終わったら外します。
3. VS Code / Copilot CLI のツール自動承認（「常に許可」）は、`gpu_profile_run` には使わないでください。
4. 本番のシークレット管理には GitHub Secret Scanning や Push Protection を併用してください。
